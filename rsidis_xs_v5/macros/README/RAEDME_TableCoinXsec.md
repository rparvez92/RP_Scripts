# README — `TableCoinXsec.C` (R‑SIDIS `rsidis_xs_v5`)
**Filename:** `macros/TableCoinXsec.C`  
**README filename:** `README_TableCoinXsec.md`  
**Primary output:** cross‑section tables (CSV) used by downstream plotting/fitting macros

---

## 0) What this macro is, in one sentence
`TableCoinXsec.C` is the **compute-heavy table maker** that loops over \((p_T, z, \phi_{pq})\) bins, computes **charge‑normalized random‑subtracted DATA yields**, computes corresponding **SIMC weighted yields**, and writes out a **bin-by-bin extracted cross section**
\[
\sigma_{\text{data}} \equiv \left(\frac{Y_{\text{net,data}}}{Y_{\text{sim}}}\right)\,\sigma_{\text{model}}
\]
**without making plots**.

Downstream macros (e.g., `PlotCoinXsec.C` and fit/overlay scripts) should read the CSV(s) and decide what to draw, what to reject, and how to treat outliers.

---

## 1) Why this exists (design philosophy)
This file was written so that:

1. **Computation and visualization are decoupled**
   - Producing yields and cross sections requires many file opens, histogram fills, and random-subtraction steps (slow).
   - Plotting and fitting are interactive tasks that should be fast and repeatable.

2. **No bin is silently dropped**
   - Even bins that are MC-starved, negative, large-error, etc. are still written.
   - Quality is communicated via **flag bits** and a **default-valid** field, rather than deleting rows.

3. **Reproducibility**
   - The CSV includes the critical scalings (e.g., SIM normalization pieces), counts, errors, and notes.

## 2) Inputs, outputs, and directory expectations

### 2.1 How you run it
From the `rsidis_xs_v5/` directory:

```bash
# SINGLE setting (manifest points to one setting directory)
root -l -b -q 'macros/TableCoinXsec.C("settings/.../manifest.txt", "results", "settings")'

# GROUP overlay mode (a .list file containing multiple settings)
root -l -b -q 'macros/TableCoinXsec.C("groups/.../grp_*.list", "results", "settings")'
```

The wrapper function `TableCoinXsec(...)` automatically chooses mode:
- if `manifestPath` ends with `.list` → **GROUP**
- else → **SINGLE**

### 2.2 Required files on disk (per setting leaf directory)
For each **setting leaf directory** (the directory containing the manifest):

- `runs_signal.txt`
- `runs_dummy.txt`
- `runs_positron.txt`
- `runs_positron_dummy.txt`
- `run_metadata.csv`
- `sigma_model.txt` (recommended; if missing, defaults to `1.0` with a warning)

These files are read in `TableCoinXsec_Single()` and again per-curve in `TableCoinXsec_Group()`.

### 2.3 DATA ROOT files location
For each run number `run`, DATA is expected at:

```
./Pass0_SkimmedDataROOTfiles/skimmed_coin_replay_production_<run>_-1.root
```

This is hard-coded in:

- `static std::string DataRootPath(int run)`

So **your working directory matters**: the macro expects
`Pass0_SkimmedDataROOTfiles/` relative to where ROOT is launched.

### 2.4 SIM ROOT files location + SIMC `.hist` location
For a given `settingId`, SIM files are expected at:

```
<projectRoot>/Pass0_SimROOTfiles/<settingId>/*.root
```

Where:
- `projectRoot = dirname(settingsRoot)` (after normalization)

Normalization **must** come from the corresponding SIMC `.hist` file, found “next to” the SIM root:
- if SIM root is `something.root` → reads `something.hist`

This is enforced by:

- `GrabNormfacFromHist(simRootPath, ...)`

### 2.5 Outputs

#### SINGLE setting mode
Writes:
- `results/<setting_id>/tables/xsec_phipq_z_pt_overlayed_single.csv`
- `results/<setting_id>/log_table.txt`

#### GROUP overlay mode
Writes:
- `results/<group_id>/tables/xsec_phipq_z_pt_overlayed_group.csv`
- `results/<group_id>/log_table.txt`

## 3) CSV schema (what columns mean)

### 3.1 Header row
The CSV header is generated by:

- `static std::string TableHeader()`

It is kept stable so plotters can rely on ordering.

### 3.2 Sentinel convention: `kMissing = -999`
The macro uses a sentinel value **only for undefined/uncomputed quantities**, for example:
- cross section when `ySim <= 0`
- relative error when denominator is zero
- any NaN/Inf results after sanity checks

Bad-quality but finite numbers (e.g., negative yields) are **preserved**, not replaced, and are marked via flags.

### 3.3 The main physics columns
Key columns you will commonly use downstream:

- `y_sig, y_pos, y_dum, y_posdum`  
  Charge-normalized yields for each category (already random-subtracted).
- `y_net, y_net_err`  
  Net yield after positron and dummy subtraction (see Section 4).
- `y_sim, y_sim_err`  
  SIMC weighted yield with correct normalization (see Section 5).
- `sigma_model`  
  Value read from `sigma_model.txt` (or 1.0 default).
- `xsec, xsec_err`  
  Extracted cross section and propagated stat error.
- `flag_bits, valid_default, note`  
  Quality metadata (see Section 7).

## 4) Physics goal and DATA yield definition

### 4.1 What “yield” means here
Within a given \((p_T, z, \phi_{pq})\) bin, a **DATA yield** is intended to represent:
- the number of coincidence events in that bin,
- **normalized to beam charge** (mC),
- corrected (run-by-run) for:
  - prescale,
  - HMS efficiency,
  - computer livetime,
- and with **random coincidences subtracted** using coincidence-time sidebands.

Formally, per run \(r\) you can view it as:
\[
Y_r \equiv \frac{1}{Q_r}\sum_{i \in \text{bin}}\; w_r\;\;-\;\;\text{(random subtraction)}
\]
where
- \(Q_r\) is the run charge in mC (`BCM4A_Q` from `run_metadata.csv`)
- \(w_r = \dfrac{\text{ps\_factor}}{\text{hms\_eff}\cdot\text{comp\_lt}}\)
- the subtraction is done in coincidence time using `CoincidenceRandomSubtraction.h`.

The macro accumulates \(\sum_r Y_r\) across runs in a category.

### 4.2 Event selections: base cuts + kinematic bin cuts

#### In SINGLE mode
`dataCuts` includes (HMS + SHMS):
- HMS and SHMS momentum acceptance (`dp`) windows
- HMS and SHMS angular acceptance (`th`, `ph`) windows
- PID cuts: HMS calorimeter and Cerenkov, SHMS calorimeter

See `TableCoinXsec_Single()` for the exact expression.

#### In GROUP mode
`dataCuts` is intentionally simpler (dp + PID only), matching `PlotCoinXsec_Group` defaults.

#### Kinematic bin cuts
For each bin:
- `kinData` restricts `pt`, `z`, and \(\phi_{pq}\) using the DATA variables:
  - `pt`
  - `z`
  - `P_kin_secondary_ph_xq` (wrapped into \([0,2\pi)\))

Kinematic cuts are built per-bin via:

- `const TCut kinData = Form("(...)", ...)`

and combined with base cuts inside `ComputeOneBin()`.

### 4.3 Coincidence random subtraction (accidentals)
This is a core physics step, because coincidence spectra always contain:
- a true coincidence peak,
- plus accidental/random background.

This macro:
1. Computes coincidence windows **once per run** (cached):
   - `ComputeCoincidenceRandomSubtraction(T, baseCuts, cfg)`
2. Fills a 1-bin histogram with *random-subtracted* yield:
   - `FillRandomSubtractedHistogramWithWindows(...)`

That fill returns:
- `sumw` = net yield in the 1-bin histogram
- `sumw2` via histogram bin error squared (used for propagation)

Additional diagnostics are recorded per category:
- `nAll`, `nBase`, `nFull` (counts after progressively tighter selections)
- `nWide` (events inside a wide coincidence gate)
- `nCoin` (events inside the chosen coin window)

These counts are valuable for spotting:
- broken PID,
- wrong coincidence branch,
- or pathological bins near acceptance edges.

## 5) Dummy subtraction and positron subtraction (net yield)

The macro supports four DATA categories per bin:

- **sig**: signal (e.g., LH2 \(\pi^+\) coincidence sample)
- **pos**: positron sample corresponding to signal kinematics
- **dum**: dummy target sample
- **posdum**: positron sample from dummy target

All four yields are computed with identical logic; only run lists differ.

### 5.1 Dummy scale factor
A fixed wall-thickness ratio is used:

- `wall_thickness_ratio = 3.82`
- `dumScale = 1.0 / wall_thickness_ratio`

Interpretation: dummy yield is scaled down to match the effective material thickness relative to the real target walls.

### 5.2 Net yield formula
Implemented in `ComputeOneBin()`:

\[
Y_{\text{net}} \;=\; (Y_{\text{sig}} - Y_{\text{pos}})\;-\; \alpha\,(Y_{\text{dum}} - Y_{\text{posdum}})
\]
where \(\alpha = \texttt{dumScale}\).

This attempts to remove:
- charge-symmetric background (positrons),
- and target-wall background (dummy),
without requiring detailed modeling of each background component.

### 5.3 Statistical uncertainty on the net yield
Assuming the four components are statistically independent:

\[
\sigma^2(Y_{\text{net}})=
\sigma^2(Y_{\text{sig}})+\sigma^2(Y_{\text{pos}})
+\alpha^2\big(\sigma^2(Y_{\text{dum}})+\sigma^2(Y_{\text{posdum}})\big)
\]

This is exactly how the code builds `eNet2` and `o.eNet`.

## 6) SIMC yield and normalization (critical!)

### 6.1 What SIM yield represents
The SIM yield here is the Monte Carlo integral (within the same bin and acceptance cuts) of:
- the event weight (`Weight` from SIMC),
- multiplied by a correct absolute normalization factor from SIMC (`normfac`),
- divided by number of generated events \(N_{\text{gen}}\).

In code:
- `simWeightExpr = Weight * normfac * (1/nGenSim)`

### 6.2 Why `normfac` is read from `.hist`
SIMC writes a text summary (`.hist`) containing a “normfac” that encodes the absolute scaling needed to convert weighted events into a physically meaningful yield.

This macro **refuses** to proceed if it cannot find a positive finite `normfac`.

Implemented by:
- `GrabNormfacFromHist(...)`

### 6.3 SIM cuts and variable definitions
The SIM selection must match the DATA selection **as closely as practical**.

SIM variables:
- `pt = sqrt(pt2)`
- `z = z`
- `phi = phipq` wrapped into \([0,2\pi)\)

SIM base cuts differ by mode:
- SINGLE: delta + xptar + yptar style acceptance cuts for both arms
- GROUP: only delta windows (broader), matching the group plotting defaults

### 6.4 SIM yield error model (statistical)
SIM yield is computed by summing weights and squared weights:
- \(Y_{\text{sim}} = \sum w_i\)
- \(\sigma^2(Y_{\text{sim}}) = \sum w_i^2\)

This corresponds to treating each weighted event as an independent contribution.

Implemented in:
- `SimYieldSum(...)`

## 7) Cross-section extraction and error propagation

### 7.1 “Ratio method” cross section
The extraction is:

\[
\sigma_{\text{extracted}} \equiv \left(\frac{Y_{\text{net}}}{Y_{\text{sim}}}\right)\sigma_{\text{model}}
\]

Where:
- \(Y_{\text{net}}\) is your background-subtracted, charge-normalized DATA yield
- \(Y_{\text{sim}}\) is the acceptance-folded SIM yield for the same bin
- \(\sigma_{\text{model}}\) is a model cross section (or structure function) value stored in `sigma_model.txt`

**Interpretation:** SIMC “knows” the acceptance and resolution effects. By taking the ratio, you largely cancel those effects, converting the DATA yield into a physics cross section *relative to the model*.

### 7.2 Error propagation used by the macro
If \(Y_{\text{sim}}>0\), then:

\[
\frac{\sigma_{\sigma}}{\sigma} =
\sqrt{\left(\frac{\sigma_{Y_{\text{net}}}}{Y_{\text{net}}}\right)^2
+\left(\frac{\sigma_{Y_{\text{sim}}}}{Y_{\text{sim}}}\right)^2}
\]

and:
\[
\sigma_{\text{err}} = |\sigma| \cdot \frac{\sigma_{\sigma}}{\sigma}
\]

**Important:** This is **statistical** error only. It does not include:
- model uncertainty,
- radiative corrections uncertainty,
- acceptance mismatch systematic,
- tracking efficiency uncertainty beyond what is encoded in `hms_eff`,
- charge calibration systematics, etc.

Those belong in a higher-level systematic study, not in this table maker.

## 8) Guards, filters, and “could we lose good physics?”
This is a key point: **the macro does not remove bins**. It only **flags** them and sets `valid_default`.

### 8.1 Why guards exist
In coincidence SIDIS-like analyses, some bins are problematic:
- near acceptance edges (especially in \(\phi\))
- in low-statistics corners of phase space
- when background subtraction dominates

Guards help downstream plotters avoid drawing nonsense by default, while still keeping the raw information available.

### 8.2 Guard configuration (`GuardCfg`)
Defaults:
- `minSimYield   = 0.05`
- `maxRelSimErr  = 0.35`
- `maxRelXsecErr = 0.50`

Used in:
- `FinalizeFlagsAndValidity(...)`
- MC-starvation checks inside `ComputeOneBin(...)`

### 8.3 Typical physics failure modes and what flags tell you

#### (A) MC empty or MC starved
- **MC_EMPTY**: `sim.nSel <= 0`
- **SIM_ZERO**: `ySim <= 0`
- **MC_STARVED**: `ySim < minSimYield` or `relSim > maxRelSimErr`

Physics interpretation:
- Your MC did not populate that bin (or barely did), so the ratio method becomes unstable.
- This commonly happens at phase-space edges or when binning is too fine.

Could this reject good physics?
- Yes, *sometimes*. A bin can contain real DATA but be MC-starved due to insufficient MC statistics, not because the physics is wrong.
- The correct response is typically: **generate more MC** or **widen bins**, not to discard DATA.

#### (B) Negative net yield
- **NET_NEGATIVE** set when background subtraction produces \(Y_{\text{net}} < 0\)

Physics interpretation:
- This usually means the bin is dominated by statistical fluctuations or subtraction terms.
- It does not necessarily mean “unphysical”; it often means “not statistically significant.”

Could this hide a real effect?
- If a bin has low net yield but significant uncertainty, it may fluctuate negative.
- The correct treatment is to keep it (as the macro does) and let fits/plotters decide.

#### (C) Large relative errors
- **MC_BAD_RELERR**, **XSEC_BAD_RELERR**

Physics interpretation:
- The bin exists but has too large fractional uncertainty to be stable.

Could strict thresholds lose good data?
- Yes, thresholds are analysis choices.
- That’s why this macro only sets `valid_default`: you can loosen/tighten later.

### 8.4 `valid_default` meaning
`valid_default = 1` means:
- none of the “default reject” flags are present.

But you are free to redefine validity in plotters, e.g.:
- allow `MC_STARVED` if you trust those bins,
- or reject bins with `NET_NEGATIVE`, etc.

## 9) Code structure (schematic map)

### 9.1 High-level call graph

```
TableCoinXsec(manifestPath, resultsRoot, settingsRoot)
 ├─ if manifestPath endswith ".list":
 │    └─ TableCoinXsec_Group(...)
 │         ├─ ReadGroupListFile(...)
 │         ├─ for each curve(setting) in group:
 │         │    ├─ ReadRunList(...) x4
 │         │    ├─ LoadRunMetadataCSV(...)
 │         │    ├─ ReadSigmaModel(...)
 │         │    ├─ Build SIM chain + GrabNormfacFromHist(...)
 │         │    └─ for bins (pt, z, phi):
 │         │         └─ ComputeOneBin(...) → write CSV row
 │         └─ done
 └─ else:
      └─ TableCoinXsec_Single(...)
           ├─ ReadRunList(...) x4
           ├─ LoadRunMetadataCSV(...)
           ├─ ReadSigmaModel(...)
           ├─ Build SIM chain + GrabNormfacFromHist(...)
           └─ for bins (pt, z, phi):
                └─ ComputeOneBin(...) → write CSV row
```

### 9.2 “ComputeOneBin” internal workflow
`ComputeOneBin()` is the physics core.

```
ComputeOneBin(...)
 ├─ CategoryYield(runs_sig)    → o.sig
 ├─ CategoryYield(runs_pos)    → o.pos
 ├─ CategoryYield(runs_dum)    → o.dum
 ├─ CategoryYield(runs_posdum) → o.posdum
 ├─ build net yield:
 │    yNet = (sig - pos) - dumScale*(dum - posdum)
 │    eNet = sqrt(sig2 + pos2 + dumScale^2*(dum2 + posdum2))
 ├─ SIM:
 │    sim = SimYieldSum(simChain, simWeightExpr, simCuts && kinSim)
 │    ySim, eSim from sumw and sumw2
 ├─ xsec:
 │    xsec = (yNet/ySim) * sigmaModel
 │    xsecErr propagated
 └─ flags + valid_default:
      FinalizeFlagsAndValidity(...)
```

## 10) Function-by-function reference (what each does)

### 10.1 Path/string helpers
- **`NormalizeSlashes(s)`**  
  Cleans repeated slashes and trailing slash issues so paths compare reliably.

- **`Dirname(p)` / `Basename(p)`**  
  Minimal filesystem split utilities (no `std::filesystem` dependency).

- **`EndsWith(s, suf)`**, **`StripExtension(path)`**, **`SwapExtension(path, newExt)`**  
  Used for mode choice and `.root` → `.hist` mapping.

### 10.2 SIM normalization helpers
- **`GetFirstRootFileFromChain(TChain&, log, simGlobForMsg)`**  
  Forces the chain to open a file by calling `GetEntry(0)` and returns the path to that actual file. Exits if chain is empty.

- **`GrabNormfacFromHist(simRootPath, histPathOut, log)`**  
  Opens the matching `.hist` text file, searches the `MISCELLANEOUS` section for `normfac = ...`, validates positivity, and returns it. Exits on failure (intentional: incorrect normalization is worse than no output).

### 10.3 Setting ID / run list parsing
- **`MakeSettingIdFromManifestPath(manifestPath, settingsRoot)`**  
  Derives a consistent `setting_id` relative to the settings tree. This is crucial because it determines both results directory and SIM globbing path.

- **`MkdirP(path)`**  
  ROOT wrapper for `mkdir -p`.

- **`ReadRunList(path)`** (+ overload with logging)  
  Reads integer run numbers from text file; strips comments `#` and whitespace.

### 10.4 CSV helpers and nominal kinematics
- **`SplitCSVLine(line)`**  
  A minimal CSV splitter that handles quoted fields.

- **`ParseEncodedNumber(enc, out)`** and **`ExtractNominalKinFromSettingId(settingId, xB, Q2, z)`**  
  Extracts nominal kinematics from tokens like `x0p25`, `q23p3`, `z0p36` in the `setting_id`.

### 10.5 Run metadata
- **`LoadRunMetadataCSV(csvPath, outMap)`**  
  Parses `run_metadata.csv` into a map keyed by run number, extracting:
  - `BCM4A_Q` (charge)
  - `h_esing_Eff` (HMS efficiency)
  - `ps5` (prescale factor)
  - `comp_livetime` (computer livetime)
  plus optional `x_Bj`, `Q2` if present.

- **`ChargeWeightedMean(runs, runInfo, wantXB)`**  
  Computes charge-weighted mean xB or Q2 from the run metadata.

- **`ReadSigmaModel(leafDir, log)`**  
  Reads `sigma_model.txt` (single number). If missing or invalid, uses 1.0 with warning.

### 10.6 Binning
- **`PhiEdgesN(n)`**  
  Creates uniform edges from \(0\) to \(2\pi\).

- **`struct Binning`**  
  Default SINGLE-mode edges:
  - `ptEdges = [0.0, 0.10, 0.20, 0.30, 0.40]`
  - `zEdges  = [0.30, 0.40, 0.50, 0.60, 0.70]`
  - `phiEdges = 16 bins over [0,2π]`

  GROUP mode overrides:
  - `zEdges = [0.0, 1.0]` (integrated over z)
  - optional wide pt overlay support (currently disabled by `overlayWidePt=false`)

### 10.7 Yield computation
- **`struct YieldEx`**  
  Stores yield and counts for one category over many runs.

- **`AddYieldFromRun(TTree* T, cutsExpr, weightExpr, cfg, win, baseCutsExpr)`**  
  Core per-run yield extraction:
  - counts events at several selection stages
  - applies coincidence wide gate and coin gate counts
  - fills a 1-bin histogram using random subtraction windows
  - returns `sumw` and `sumw2`

- **`struct SimYieldEx`** and **`SimYieldSum(sim, exprWeight, cutBool)`**  
  Monte Carlo yield in a bin:
  - uses `TChain::Draw("weight", "cuts", "goff")`
  - sums weights and weights^2 for error

### 10.8 Flags and default validity
- **`enum FlagBits`**  
  Bitmask encoding quality issues:
  - MC empty / starved / bad relative error
  - net negative / NaN / zero
  - sim NaN / zero
  - xsec NaN / negative / bad rel err / zero err

- **`SafeRelErr(v,e)`**  
  Computes \(|e/v|\) safely; returns `kMissing` if invalid.

- **`FinalizeFlagsAndValidity(BinOut&, GuardCfg&)`**  
  Converts flags → human note tokens and sets `valid_default`.

### 10.9 Group list reader
- **`ReadGroupListFile(groupPath, settingsRoot, log)`**  
  Reads a `.list` file where each non-comment line is:
  ```
  <curve_label> <manifest_path>
  ```
  Supports relative manifest paths (relative to the group file directory).

## 11) Practical debugging checklist (when numbers look weird)

### 11.1 If SIM is empty or starved
- Check your SIM glob in the log:
  - `SIM glob: ... added=<n>`
- Confirm `nGenSim > 0`.
- If only some bins are starved:
  - MC statistics may be insufficient
  - binning may be too fine (especially in \(\phi\))

### 11.2 If yields are near zero but xsec explodes
That typically means:
- \(Y_{\text{sim}}\) is tiny (MC-starved)
- or \(Y_{\text{net}}\) is a subtraction of similar-sized numbers

Use columns:
- `y_net`, `y_sim`
- `rel_net_err`, `rel_sim_err`
- `flag_bits`, `note`

### 11.3 If net yields go negative “everywhere”
Common causes:
- wrong positron category (wrong runs list)
- dummy scale factor mismatch
- coincidence random subtraction windows not appropriate (wrong coincidence time branch)
- PID/cuts mismatch between signal and background categories

### 11.4 If single mode and group mode disagree strongly
That is expected if:
- SINGLE applies tighter angular acceptance cuts and group mode doesn’t
- z binning differs (single has multiple z bins; group integrates)

## 12) How to customize safely (typical modifications)

### 12.1 Change binning
Modify `struct Binning` defaults or group overrides.  
If you change the schema significantly, bump:
- `schema_version` (currently `1`)

### 12.2 Change coincidence-time branch
Update:
- `cfg.CtBranchName = "CTime_ePiCoinTime_ROC2";`

Make sure the branch exists in your skimmed trees.

### 12.3 Tune guards
Change defaults in `GuardCfg` or override in group/single.
Remember: guards only affect `valid_default`, not table contents.

### 12.4 Change base cuts
Edit `dataCuts` and `simCutsBase` in the relevant mode function.
**Keep data and sim cuts consistent** in meaning, even if variable names differ.

## 13) FAQ (questions a new analyzer will ask)

### Q: Why does the table keep “bad” bins?
Because “bad” is often a downstream decision:
- A bin might be MC-starved today but become usable after regenerating MC.
- A negative yield might become positive with more statistics or improved background modeling.
Keeping everything makes the pipeline auditable.

### Q: What is `sigma_model.txt` supposed to be?
It is the model cross section (or structure-function-based cross section) value used for the ratio method. Conceptually, it is the \(\sigma_{\text{model}}\) in:
\[
\sigma_{\text{extracted}} = (Y_{\text{data}}/Y_{\text{sim}})\,\sigma_{\text{model}}
\]
If you set it to 1, the CSV xsec becomes essentially a “data/sim ratio” in cross-section units.

### Q: Why is SIM normalization `normfac/nGenSim`?
- `normfac` gives absolute scaling (SIMC-defined).
- dividing by number of generated events converts the weighted sum into the correct integral estimate.

### Q: Why do we include prescale, efficiency, and livetime in a per-run weight?
Because different runs can have different DAQ conditions. If you simply sum counts without correcting, runs with lower livetime (or different prescales) would bias the yield.

### Q: Could tight cuts remove real physics?
Yes. Any acceptance/quality cut can remove good events near edges.
That’s why:
- single mode uses stricter “nominal acceptance” cuts (safer comparisons)
- group mode uses looser cuts for broad overlays
And why the macro preserves counts (`nAll`, `nBase`, `nFull`, `nWide`, `nCoin`) so you can diagnose over-cutting.

## 14) Final “mental model” for a newcomer
Think of `TableCoinXsec.C` as producing a **3D grid of bins**. For each bin it computes:

1. **DATA net yield**: signal minus backgrounds, random-subtracted, corrected for run conditions, normalized by charge.
2. **SIM yield**: MC integral in the same bin with correct absolute normalization.
3. **Cross section**: scale the data/sim ratio by the model.

Everything else (flags, notes, validity) exists to help later macros decide **what is trustworthy to plot or fit**.
